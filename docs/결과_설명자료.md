## 1. 문제 정의

제주빅데이터센터 분석실은 카드·유동인구처럼 **센터 안에서만 볼 수 있는 데이터**를 제공하지만, 방문자(대다수 기관·기업 실무자, 목적: 논문·현황자료·사업계획서 — 센터 답변 2026.11.01)는 네 가지 벽에 부딪힙니다.

| 벽 | 내용 |
|---|---|
| 탐색 | 71종 데이터(명세서 74개 시트) 중 무엇을 어떤 조건으로 받아야 할지 모름 |
| 수집 | 조회·다운로드가 **1개월 단위** → 1년치 분석에 데이터당 CSV 12개, 정리·병합 부담 |
| 분석 | 코딩·통계 역량 부족, 시간 제약(방문 이용) |
| 반출 | 10 미만 수치·역산 가능한 표·텍스트/스프레드시트 형식은 **반출 불가** → 반려·재방문 |

**오름의 목표**: 질문 한 줄에서 출발해 *데이터 안내 → 센터 PC 안의 분석 → 반출 기준 자동 준수 → 보고서·반출 신청서 초안*까지 한 번의 방문으로 끝낸다.

## 2. Agent 구조

```
질문 ─▶ 계획 Agent(AI: gpt-6-luna high · 도구 5종 find_region/find_industry/find_festival/search_datasets/get_dataset · 최대 3단계 / 키 없으면 규칙이 같은 도구를 정해진 순서로)
      ─▶ Resolver(법정동·행정동·권역·업종·축제 사전) ─▶ Navigator(데이터 체크리스트: 데이터명·기간·조건·이유)
      ─▶ Ingestor(CSV 자동 인식·병합) ─▶ Hub Tool(제주데이터허브 실데이터·Open API: 필요한 지역·기간만 조회, 캐시·쿼터 보호)
      ─▶ Analyzer(상권·축제·버스 분석 도구, 로컬 pandas) ─▶ Export Guard(반출 기준 검사·교정)
      ─▶ Narrator(AI, 검사 통과 집계표만) ─▶ Verifier(문장 속 수치 근거 대조, 불일치 시 재작성)
      ─▶ Reporter(PDF·DOCX·PNG·반출 신청서 초안) ─▶ Follow-up Agent(AI가 도구를 골라 호출: 지역 비교·재분석·표 조회·지표 설명)
```

| 구성 | 역할 | 구현 |
|---|---|---|
| 계획 Agent | 질문 → 분석 유형·지역·업종·행사·비교지역·데이터 선택(이유 포함)·활용 목적 | `app/agent/planner.py` (JSON Schema 구조화 출력, 도구 5종 최대 3단계 호출, 규칙 기반 대체) |
| Resolver/Navigator | 자연어 지역·업종·축제 해석, 필요한 데이터·기간·조건 안내 | `app/agent/resolve.py`, `app/catalog/*` |
| Ingestor | 헤더↔명세서 71종 대조로 데이터 종류 자동 인식, 월별 병합·중복 제거·빠진 기간 탐지 | `app/ingest/loader.py` |
| Hub Tool | 센터 CSV가 없으면 허브 실데이터(746·748·793·761·512)와 Open API(583·612·613)로 분석, 키가 있으면 583을 직접 호출 | `app/hub/public_data.py`, `client.py`, `app/agent/resolve.py` |
| Analyzer | 결정적 계산(같은 입력 → 같은 결과) | `app/analysis/trade_area.py`, `event_impact.py`, `transit.py` |
| Export Guard | 반출 정책 구현(범주처리·삭제처리·보완 억제·기반 건수 규칙) | `app/guard/export_guard.py` |
| LLM Gate | AI로 가는 유일한 경로(검사 통과 표만), 전송 내용 감사 로그 | `app/guard/llm_gate.py`, `app/agent/llm.py` |
| Narrator/Verifier | 해석·제언·활용 문안 작성 + 수치 근거 검증 | `app/agent/narrator.py`, `rule_writer.py` |
| Follow-up Agent | AI가 도구(compare_regions·rerun_analysis·get_table·explain_method)를 스스로 골라 호출 — 매 턴 JSON 스키마로 '도구 호출/답변'을 결정, 계산은 로컬 | `app/agent/tools.py` |
| Reporter | Edge 헤드리스 PDF, python-docx DOCX, PNG 차트, 반출 패키지 ZIP | `app/report/*` |

**판단·자율 범위** — AI가 판단: 도구 선택과 데이터 선택(이유 포함), 질문 해석, 비교지역 제안, 해석·제언·문안, 후속 질문에서 도구 선택 / 코드가 전담: 모든 수치 계산, 반출 판정, 파일 처리 / 사람이 확인: 해석값 수정, 반출 신청, 퇴실 정리.

## 3. 주요 기능

1. **질문 해석 및 실시간 작업 기록** — 질문 접수 시 계획 Agent가 도구(지역·업종·축제·데이터 탐색)를 단계별로 호출하며 「오름이 한 일」에 실시간 기록 (예: "함덕 횟집 차리면?" → 창업·상권 / 지역 함덕(조천읍) / 업종 한식 음식점업)
2. **데이터 길잡이 및 AI 추천** — 오름이 고른 데이터와 체크리스트 AI 선택/AI 추천(선택 이유 제시). (예: 방어축제 → 「내국인 유동인구(읍면동)_v01」 2024.11~2024.12, 행정동=대정읍·안덕면·한경면 …)
3. **범위 밖 질문의 데이터 탐색** — 3대 분석(상권·축제·버스) 외 질문도 71종 데이터셋을 검색해 맞춤 데이터 안내 (예: 와이파이 질문 → 4-05 AP별 이용 현황, 4-01 AP 현황)
4. **CSV 자동 인식** — 파일명과 무관하게 열 이름으로 데이터 종류·버전(v01/v02)·기간 인식, 선택 컬럼만 받은 파일도 인식
5. **분석 도구 3종** — 상권(매출 추이·요일/시간 지수·고객·경쟁·방문인구·방문객당 소비·매력도 지수), 축제(같은 요일 기준선·이중차분·연령 구성·버스·업종 순효과), 버스(정류소 순위·저이용 정류소·요일/시간대·이용자 구성·제주 전역 추이)
   — 센터 CSV가 없어도 허브 실데이터로 바로, 넣으면 최신·세부로
6. **반출 안전장치** — 모든 표·그림·AI 입력이 같은 관문을 통과, 처리 내역이 반출 신청서 초안에 자동 기재
7. **보고서 및 결과 '작업 과정' 탭** — PDF(인쇄용)·DOCX(편집용, 한글에서 열림)·PNG 차트·반출 패키지 ZIP 생성, 웹 결과 화면에서 분석 결과·제언 외에 도구 호출과 판단 과정을 확인하는 '작업 과정' 탭 제공
8. **투명성** — 「AI 전송 기록」에서 보낸 내용·토큰·추정 비용 열람, 문장 속 수치 근거 검증 결과 표시
9. **퇴실 정리** — 세션 폴더 일괄 삭제

## 5. 검증 방법과 한계

### 검증
- 자동 테스트 196개(`run_tests.bat`): 반출 규칙(10 미만·보완 억제·기반 건수·범주처리 우선·차단), LLM 관문(비공개 셀 미전송), 수치 근거 검증, CSV 인식·병합, 분석 도구가 심어 둔 효과를 정확히 찾는지, **허브 실데이터 경로**(512 제주 전역 진단, 583·612·613 변환, 일 단위 자료의 시간대 분석 생략, 센터 CSV 없이 대표 시나리오가 끝까지 실행되는지)
- 재현·검증 도구 및 기준 공개: `tools/eval_agent.py`와 21개 벤치마크 질문·기대값 공개를 통해 누구나 동일 조건에서 계획 정확도와 E2E 파이프라인을 자동 측정·재현 가능
- 결정성: 같은 입력 → 같은 표. 허브 원본 해시와 처리 내역은 `data/public/PROVENANCE.json`, Open API 스냅샷은 `tools/fetch_hub_api.py`로 재생성
- 문장 속 수치(10 이상) 자동 대조: 근거 표에 없는 수치가 있으면 AI에 수정 요청, 남으면 화면·보고서에 표시
- 기준선의 중요성: 축제 버스 분석에서 기준선이 하루뿐일 때 −2.8%였던 값이 같은 요일 2주 기준선을 갖추자 +26.9%로 안정 — 오름은 같은 요일 기준선을 기본으로 씀

### 한계
- 계획 Agent는 AI 판단이라 호출마다 도구 순서·표현이 조금 다를 수 있음 — 분석 유형·지역·업종·날짜는 도구 결과로만 확정하고, 계산·반출 판정은 코드가 하므로 수치는 같음
- 카드 = 비씨카드 결제분(전체 소비 아님), 허브 카드 매쉬업은 2017.01~2021.05
- 유동인구 = 통신 신호 기반 추정치(허브 583은 일 단위 값 — 증감·비교 위주로 해석)
- 허브 613(카드 단말 정류소 ID)과 612(BIS 정류소 ID)는 체계가 달라 정류소 이름으로 연결(승차 기준 약 97% 일치, 양방향 합산)
- 허브 512는 제주 전역 합계 — 지역·노선별 차이는 센터 3-04·3-02로
- 상관 분석이므로 인과 단정 금지
