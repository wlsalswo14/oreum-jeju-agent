「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 제출작 **오름(OREUM)**

필수 데이터 조건: 제주빅데이터센터 또는 제주데이터허브 데이터 1종 이상 → **제주데이터허브 실데이터 8종(공개 파일 5종 + Open API 3종)을 내장·호출**하고, **센터 데이터 9종(구버전 v01 4종 호환, 총 13종 인식)**을 넣으면 최신·세부 분석으로 확장. **가상 데이터는 쓰지 않음**(테스트용 형식 검증 데이터만 별도).

- 키가 있으면: 질문한 지역·기간이 스냅샷에 없을 때 Agent가 583을 직접 조회(읍면동 필터, 100건/쪽 페이지 처리, 디스크 캐시, 데이터별 일일 1,000회 쿼터 보호). 호출 내역은 화면 진행 기록에 표시.

- 583은 일 단위 값(성·연령별)으로, 분석은 같은 요일 기준선·이중차분처럼 **상대 비교**에 사용(절대 인원 해석 지양).

## 3. 수집·전처리·분석 흐름

```
[센터 조회 화면] 1개월 CSV ──▶ ① 자동 인식(헤더 ↔ 명세서 71종 대조, v01/v02 구분, 선택 컬럼만 있어도 인식)
                               ② 병합(여러 달) · 중복 제거 · 결측(NA) 처리 · 숫자형 변환 · 빠진 기간 탐지
[허브 실데이터(내장)·Open API] ▶ ③ 지역·업종 사전으로 표준화(법정동↔행정동↔7권역, BC 42업종↔상가 업종, 정류소 이름 연결)
                               ④ 로컬 분석(결정적 계산: 추세·요일/시간 지수·고객 구성·경쟁·유동인구·이중차분·첨두 집중도)
                               ⑤ 반출 검사(10 미만 범주처리/삭제처리 + 역산 방지 보완 억제, 기반 건수 규칙)
                               ⑥ 차트(PNG)·LLM 해석(검사 통과 집계표만)·수치 근거 검증
                               ⑦ 보고서(PDF·DOCX) + 반출 신청서 초안(자료별 출처·가공 방식·활용 사유)
```

- 원본 행은 화면·보고서·LLM 어디에도 출력하지 않음(반출 정책: `data.head()` 출력 결과 포함 시 반출 불가).
- 업로드 CSV·결과는 세션 폴더에만 저장, 퇴실 정리 시 삭제.

### 계획 단계의 데이터 탐색
분석 실행 전 계획 단계에서 Agent가 `search_datasets`와 `get_dataset` 도구로 명세서 카탈로그를 검색해 데이터를 고르고, 고른 이유를 화면과 체크리스트에 표시합니다.
- **카탈로그 원천**: 제주빅데이터센터 데이터 명세서(`spec_catalog.json`, `tools/build_catalog.py` 생성), 제주데이터허브 공개 데이터 목록 중 오름이 내장한 데이터.
- 계획 Agent는 데이터 값(원본 행·집계값)은 보지 않고 공개 명세 요약(ID·이름·기간·갱신 주기·반출 등급·설명)만 조회하여 분석에 적합한 데이터셋을 선정합니다.

## 4. 테스트용 형식 검증 데이터 (화면·보고서에서는 쓰지 않음)

- 시연·결과물은 모두 위 **실데이터**로 만든다. 화면의 '가상 데이터 불러오기' 기능과 설치 시 가상 데이터 생성 단계는 제거했다.
- 다만 센터 CSV 인식·병합·반출 검사 같은 **센터 데이터 경로**는 센터 밖에서 실데이터로 시험할 수 없으므로, 명세서 v13 형식을 따른
  테스트 전용 데이터를 `tools/make_demo_data.py`로 만들어 자동 테스트(`tests/`)에서만 사용한다(고정 시드, 파일명 `SYNTHETIC_` 표시).
- 업로드된 파일이 이 형식 검증 데이터이면 화면·보고서에 '가상' 경고가 자동으로 붙는다.
